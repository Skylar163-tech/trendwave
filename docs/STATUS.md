# 项目现状（MVP）

更新日期：2026-08-11

## 定位

电商媒体热点营销工作台 MVP：运营在后台配置提示词 / 模型 / 商品 / 信源，在工作台走完「热点 → 选品 → 文案 → 审核」闭环。演示可用；真实发微博尚未接入。今日头条热榜已走真实接口；微博等其余内置榜仍为 mock。

## 主路径（五步）

1. **新闻抓取** — 后台信源（今日头条热榜真实拉取；其余内置榜仍为 mock；RSS 为真实拉取）+ 借势硬边界审核（`newsGate`）；列表为多列卡片网格
2. **建议匹配** — LLM / 规则按热点从商品库推荐（`productMatch`），点选采纳
3. **确认匹配** — 人工终审；可保留建议或全库分页补选，最终绑定
4. **创作文案** — 后台提示词 + `AppConfig.model`（mock / direct / proxy）+ 机审与可选返工
5. **审核并发送** — 微博预览与模拟发布

## 架构决策

| 决策 | 说明 |
|------|------|
| 后台控主路径 | 文案与抓取以 `AppConfig` 为准，不依赖扣子 |
| 扣子旁路 | 仅顶栏集成配置「测试调用」；不拦截工作台步骤 |
| 建议 / 确认分步 | 建议页专注 AI；确认页做终审与全库补选（分页 + 吸底下一步） |
| 配置三级 | `server/data/config.json` → localStorage → 代码默认值 |
| 信源分层 | RSS + 今日头条热榜走服务端真实拉取；其余内置热榜仍为演示 mock |

## 真实数据怎么跑

1. `npm run server` + `npm run dev`（RSS / 热榜必须经 8787，仅开前端会回退演示）
2. 运营后台「模型」：`proxy` 或 `direct` + API Key，测通后再生成文案
3. 商品：CSV / Excel 导入或后台编辑（勿提交含密钥的 `config.json`）
4. 热点：启用「今日头条热榜」，或添加可访问的 RSS（推荐 `https://www.36kr.com/feed`）
5. 信源页「测试全部来源」可先验证连通，再回工作台「立即抓取」

不需要数据源 MCP；不需要扣子即可验提示词效果。

## 提示词默认能力（2026-08-11）

默认提示词已按运营可用模板沉淀，并适配本仓库解析契约（勿改成纯文本 `SKIP_*` 或「推荐决策」多字段报告）：

| 后台区块 | 能力来源 | 输出契约 |
|---------|---------|---------|
| 借势硬边界 | 新闻安全审核 | JSON `results[]`：`clear` / `needs_review` |
| 商品智能匹配 | 选品 / 自然关联 | JSON `matches[]`：商品库 `productId`；无关联则 `[]` |
| 角色 + 素材模板 | 微博文案专家 | 纯微博正文（80～180 字），供机审 / 返工 |

## 已知边界

- 微博 / 知乎 / 抖音内置热榜仍为演示数据；今日头条已接真实热榜
- 部分「看起来像 RSS」的地址会返回空正文或反爬 HTML（如 `zhihu.com/rss`、`36kr.com/newsflashes.xml`）；服务端会判无效并提示，工作台无有效条目时回退演示列表
- 发布为模拟，无真实发帖
- 扣子全流程灌入已从主路径移除，代码保留供连通测试
- `server/data/config.json` 已 gitignore，含密钥时勿提交
- 头条号「内容源接入」RSS 规范是媒体投稿格式，不是可订阅的热榜地址
